### 0.3 三个必须先知道的事实

**事实一：`world ↔ actors` 在目录粒度上是双向的，README 的"单向无循环"不成立。**

- `world → actors`：16 条。8 个街区组件 import `../actors/npc.js` 与 `../actors/models.js`；`world/props.js`、`world/beach.js` import `../actors/models.js`。
- `actors → world`：2 条。`actors/player.js:5` 与 `actors/camera-rig.js:4` 都 `import { groundH } from '../world/island.js'`。

但**文件粒度上没有运行时环**：`world → actors` 的链条走到 `actors/npc/kangaroo.js` 就停了，kangaroo 只在 JSDoc 里引用 `player.js`，没有运行时 import。所以这是"目录分层味道"问题，不是运行时问题。

> 处置：`world/` 与 `actors/` 同属 `domain/`，环变成层内环，天然无害。
> 可选优化（2 行）：`groundH` 本来就由 `world/terrain.js` 导出、`island.js` 只是转出。把这两处改成 `import { groundH } from '../world/terrain.js'`，就切断了 `player.js → island.js`（门面）这条把整个 world 拉进来的边，文件级依赖图也变成无环。**建议做，但不阻塞本次重构。**

**事实二：只有 `core/` 和 `audio/` 两个目录深度不变，其余全部 +1 层。**

这是本次迁移能"零业务改动"的根本原因：源文件和目标文件同时下沉一层，相对 import 的 `../` 数量不变。只有**跨进 `core/` 或 `audio/`** 的说明符需要改写。

**事实三：全仓只有一处 `import.meta.url` 深度敏感。**

`src/core/paths.js:8` 的 `new URL('../../assets/', import.meta.url)`。它迁到 `src/shared/paths.js` 后深度不变（`src/core/` → `src/shared/`，都是 `src/` 下第一层），**这一行不用改**。这是刻意把 `shared/*.js` 摊平而不是塞进 `shared/config/` 的原因。

### 1.3 各层职责与准入清单

| 层 | 职责 | 可依赖 | 禁止依赖 |
|---|---|---|---|
| `app/` | 入口、依赖组装、启动编排 | 全部四层 | 被任何层 import |
| `domain/` | 游戏规则、世界构建、角色行为 | `domain` `infrastructure` `shared` | `app` |
| `infrastructure/` | 渲染管线、音频、输入、资源定位 | `infrastructure` `shared` | `app` `domain` |
| `shared/` | 纯函数、常量、静态数据 | `shared` | `app` `domain` `infrastructure` |

**为什么 `domain → infrastructure` 是允许的**：这不是教科书 Clean Architecture 的方向（那里 domain 不该知道渲染），但它是**本项目既有的、健康的**方向——`world → gfx` 本来就是主链 `main → game → world → gfx → core` 的一段。强行反转会让 `world/districts/*` 无法直接建几何体，等于重写。四层在这里的作用是**固化既有方向**，不是发明新方向。

**`core/input.js` 为什么进 `infrastructure/` 而不是 `shared/`**：它持有 `HTMLCanvasElement`、申请指针锁、挂键盘鼠标监听，是平台适配代码。`shared/` 只放不碰平台状态的东西（`util.js` 里的 `makeCanvas` 是纯工厂，可以留）。

**`viewer/` 为什么整体进 `app/`**：它是第二个应用入口（`viewer.html` → `src/viewer/main.js`），只 import `three` 和自身，与主游戏零耦合。放进 `app/viewer/` 表达"这是另一个 app"，而不是"这是领域的一部分"。

**迁移理由（按层）**

| 层 | 理由 |
|---|---|
| `app/` | 入口与依赖组装。`main.js` 只做"加载进度 → 标题 → 跳过开场"，`viewer/` 是第二个独立入口。放最上层，谁都不许 import 它。 |

| `shared/` | 叶子。`config`（路网常量）、`paths`（资源基址）、`math`、`util`、`data`（文案/模型表/任务表）。零上层依赖，可被任何层引用。 |

## 4. 依赖约束规则

### 4.1 允许矩阵

行 = 发起方，列 = 被依赖方。`✓` 允许，`✗` 禁止。

| ↓发起 \ 被依赖→ | `app/` | `domain/` | `infrastructure/` | `shared/` | `three` / `three/addons` |
|---|:--:|:--:|:--:|:--:|:--:|
| `app/` | ✓ | ✓ | ✓ | ✓ | ✓ |
| `domain/` | ✗ | ✓ | ✓ | ✓ | ✓ |
| `infrastructure/` | ✗ | ✗ | ✓ | ✓ | ✓ |
| `shared/` | ✗ | ✗ | ✗ | ✓ | ✓ |

补充规则：

1. **`shared/` 不许碰 DOM 状态**。`util.js` 的 `makeCanvas` 是纯工厂（建 canvas 就返回），可以留；`input.js` 持有监听器和指针锁，所以它进 `infrastructure/`。
2. **`app/` 只被 `index.html` / `viewer.html` 引用**，任何 `.js` 都不许 import 它。
3. **同层内允许任意互相引用**，包括 `domain/world ↔ domain/actors` 这种双向边（见 §0.3 事实一）。
4. **`three` 与 `three/addons/*` 是裸说明符**，不参与分层校验，任何层都可以用。

### 4.2 ESLint：`no-restricted-imports`

在 `eslint.config.js` 末尾追加。核心思路：**按层给每个层单独一段 config，把其余三层的目录名写成禁止 pattern**。

```js
// ---------- 分层依赖约束 ----------
// 方向：app ─▶ domain ─▶ infrastructure ─▶ shared
// 说明：no-restricted-imports 的 patterns 是对「说明符字符串」做 glob 匹配，
//       相对路径（../../app/x.js）也能命中 `**/app/**`。
//       它是编辑器里的即时反馈；CI 的权威门禁是 tools/ci/check-layers.mjs（真实路径解析）。
const LAYERS = ['app', 'domain', 'infrastructure', 'shared'];

/** 每层允许依赖的层（含自身）。 */
const ALLOWED = {
  app: ['app', 'domain', 'infrastructure', 'shared'],
  domain: ['domain', 'infrastructure', 'shared'],
  infrastructure: ['infrastructure', 'shared'],
  shared: ['shared'],
};

/** 为某一层生成 no-restricted-imports 的 patterns。 */
function forbiddenPatterns(layer) {
  return LAYERS.filter((l) => !ALLOWED[layer].includes(l)).map((l) => ({
    group: [`**/${l}/**`, `**/${l}`],
    message: `${layer}/ 不允许依赖 ${l}/。分层方向：app → domain → infrastructure → shared`,
  }));
}

const layerConfigs = LAYERS.map((layer) => ({
  files: [`src/${layer}/**/*.js`],
  rules: {
    'no-restricted-imports': ['error', { patterns: forbiddenPatterns(layer) }],
  },
}));

export default [
  // ...原有 ignores / 通用规则 / tests 段保持不变...
  ...layerConfigs,
];
```


**这套配置已实测验证**（ESLint 10，本机 `node_modules/.bin/eslint`）。搭一个最小骨架跑 `eslint src/`：

| 文件 | 内容 | 结果 |
|---|---|---|
| `src/shared/good.js` | `import { clamp } from './util.js'` | 通过 |
| `src/app/main.js` | 无 import | 通过 |
| `src/shared/bad.js` | `import { Game } from '../../app/main.js'` | ✗ `shared/ 不允许依赖 app/` |
| `src/infrastructure/render/bad2.js` | 同上 | ✗ `infrastructure/ 不允许依赖 app/` |
| `src/domain/game/ok.js` | `../../shared/util.js` + `../../app/main.js` | ✗ 只报 app 那条，shared 那条放行 |

```
✖ 3 problems (3 errors, 0 warnings)
```

**一个容易踩的实现细节**：`no-restricted-imports` 的 `patterns[].group` 底层用 `ignore` 包做 glob 匹配，而 `ignore` 默认**拒绝含 `..` 的路径**（`RangeError: path should be a path.relative()d string`）。ESLint 在 `lib/rules/no-restricted-imports.js:334` 显式传了 `allowRelativePaths: true`，所以相对说明符能正常匹配。**如果你自己写插件或换工具做同样的校验，记得带上这个选项**，否则 `../../app/x.js` 会直接抛异常而不是报违规。
**为什么不用 `eslint-plugin-import` 的 `import/no-restricted-paths`**：它能做真实路径解析、还自带 `import/no-cycle`，但 ESLint 10 的兼容性目前不稳，且会给这个"运行时零 npm 依赖"的项目再加一个 devDependency 和一层解析开销。用零依赖的 `tools/ci/check-layers.mjs` 承担权威判定更划算。

**为什么 ESLint 规则不能单独当门禁**：`no-restricted-imports` 的 `patterns` 匹配的是**源码里写的字符串**，不是解析后的路径。`../../app/main.js` 和 `../../../app/main.js` 都要靠 `**/app/**` 兜住；一旦有人写出 `../../foo/../app/x.js` 这种，glob 就漏了。所以：

- **编辑器**：ESLint 规则给红波浪线，改代码时立刻知道。
- **CI**：`check-layers.mjs` 做 `path.resolve` 后的真实判定，漏不掉。

### 4.3 零依赖守卫 `tools/ci/check-layers.mjs`

已随本文交付。它做三件事：

1. **分层校验**：解析每个相对说明符，算出目标文件的层，比对 `ALLOWED` 矩阵。
2. **断链校验**：说明符解析不到 `src/` 内任何文件 → 报错（迁移漏改会在这里现形）。
3. **循环依赖检测**：DFS 三色标记，只对**运行时** `from '...'` 建图；JSDoc 的 `import('...')` 类型引用只参与分层校验，不参与建图（类型引用不产生运行时环）。

### 4.4 循环依赖的处置原则

- **层内环**（`domain/world ↔ domain/actors`、`domain/game` 内部的门面互引）：允许。这是门面模式的正常代价，`Island` / `Game` 作为门面被同层模块反向引用是设计意图。
- **跨层环**：一律禁止，`check-layers.mjs` 会拦。
- **类型环**（只在 JSDoc 里互相引用）：允许，不建图。

如果将来要消掉 `domain/world ↔ domain/actors` 这条层内环，最小改动是 §0.3 事实一里那 2 行：`player.js` / `camera-rig.js` 的 `groundH` 改从 `world/terrain.js` 取，绕开 `island.js` 门面。

## 5. CI/CD 配置优化

### 5.1 路径过滤策略

新目录让"改了什么"第一次变得可判定。分三类：

| 类别 | 路径 | 触发什么 |
|---|---|---|
| **代码** | `src/**` `index.html` `viewer.html` `vendor/**` | 全量 CI：lint + 分层 + 单测 + 双构建 |
| **资产** | `assets/**` | 全量 CI（构建会把音频 base64 内嵌）+ 部署 |
| **工具链** | `scripts/**` `tools/**` `tests/**` `package*.json` `*.config.js` `.github/**` | 全量 CI |
| **纯文档** | `docs/**` `**/*.md` `LICENSE` | **跳过 CI** |
| **产物** | `dist/**` `tests/e2e/shots/**` `tools/tripo/out/**` | 已 gitignore，不会出现在 diff 里 |

用 `paths-ignore` 而不是 `paths`：`paths-ignore` 的语义是"**所有**改动路径都命中忽略列表才跳过"，所以一个同时改 `src/` 和 `docs/` 的 PR 照样跑 CI。用 `paths` 白名单反而容易漏（新增顶层目录时忘了加）。

### 5.2 `.github/workflows/ci.yml`

```yaml
name: CI

on:
  push:
    branches: [main]
    paths-ignore: &docs-only
      - 'docs/**'
      - '**/*.md'
      - 'LICENSE'
      - '.editorconfig'
  pull_request:
    branches: [main]
    paths-ignore: *docs-only

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  verify:
    name: layers + lint + unit + build
    runs-on: ubuntu-latest
    timeout-minutes: 30
    steps:
      - name: Checkout（含 LFS 资产）
        uses: actions/checkout@v4
        with:
          lfs: true

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: npm

      - name: Install
        run: npm ci

      - name: 分层与循环依赖
        run: npm run check:layers

      - name: Lint
        run: npm run lint

      - name: Unit tests
        run: npm test

      - name: Build 单文件（标准版）
        run: npm run build

      - name: Build 单文件（观景版）
        run: npm run build:viewer

      - name: 上传构建产物
        uses: actions/upload-artifact@v4
        with:
          name: dist-singlefile
          path: dist/*.html
          retention-days: 7
```

**关键点**

- `check:layers` 放在 `lint` **之前**：分层违规是架构级错误，比风格问题更该先失败。
- `lfs: true` 不能省：`assets/models/*.glb` 是 LFS 指针，不拉实体的话 `npm test` 里 `model-registry.test.js` 的磁盘交叉核对会挂。
- `paths-ignore` 用 YAML 锚点 `&docs-only` / `*docs-only` 复用，避免 push 和 pull_request 两处漂移。
- 不加 `paths` 白名单：新增顶层目录时白名单会静默漏跑。

```yaml

    workflows: [CI]
    types: [completed]
    branches: [main]

jobs:

        run: npm ci

          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}

          set -euo pipefail
```

## 6. 潜在风险提示

按"会不会静默失败"排序。**静默失败**（页面白屏、构建产物缺内容、测试假绿）比**显式报错**危险得多。

### 6.1 HTML 入口路径 —— 会白屏，但报错明确

`index.html:281` 与 `viewer.html` 的 `<script type="module" src="...">` 是硬编码路径。

```html
<!-- index.html -->
<script type="module" src="./src/main.js"></script>        <!-- 改前 -->
<script type="module" src="./src/app/main.js"></script>    <!-- 改后 -->

<!-- viewer.html -->
<script type="module" src="./src/viewer/main.js"></script>      <!-- 改前 -->
<script type="module" src="./src/app/viewer/main.js"></script>  <!-- 改后 -->
```

**importmap 不用动**：

```html
<script type="importmap">
{ "imports": { "three": "./vendor/three/three.module.js", "three/addons/": "./vendor/three/addons/" } }
</script>
```

`vendor/` 位置不变，`three` / `three/addons/` 是裸说明符，与 `src/` 内部结构无关。这是本次重构最大的运气——**如果当初把 three 也塞进 `src/`，importmap 就得跟着改，而 importmap 的路径是相对 HTML 的，改错了浏览器只在 console 里丢一句 "Failed to resolve module specifier"，页面直接白屏。**

### 6.2 构建脚本的 marker 正则 —— 会静默产出错误产物

这是**最危险的一处**。`scripts/build-singlefile.mjs` 用正则找 HTML 里的入口标记，找不到就 `throw`：

```js
// 改前
const marker = /<script type="module" src="\.\/(?:src|app)\/main\.js"><\/script>/;
// 改后
const marker = /<script type="module" src="\.\/(?:src\/app|app)\/main\.js"><\/script>/;
```

`scripts/build-viewer.mjs:20` 同理：

```js
const MARKER = /<script type="module" src="\.\/(?:src|app)\/viewer\/main\.js"><\/script>/;
// →
const MARKER = /<script type="module" src="\.\/(?:src\/app|app)\/viewer\/main\.js"><\/script>/;
```

好消息是它 `throw`，不会静默。坏消息是**只有跑 `npm run build` 才会发现**——`npm run lint` 和 `npm test` 都不碰它。所以 §3.6 的验证清单里 `npm run build && npm run build:viewer` 不能省。

顺带把 `SRC_DIR` 的双分支逻辑删掉：

```js
// 改前：Phase A 源码在 app/，cutover 后回落到 src/
const SRC_DIR = existsSync(join(ROOT, 'app', 'main.js')) ? 'app' : 'src';
const ENTRY = join(ROOT, SRC_DIR, 'main.js');
// 改后
const ENTRY = join(ROOT, 'src', 'app', 'main.js');
```

### 6.3 `paths.js` 的资源基址 —— 本次刻意规避了

```js
// src/core/paths.js:8
export const ASSET_BASE = new URL('../../assets/', import.meta.url);
```

`../../` 是**相对文件自身位置**的。`src/core/paths.js` 在 `src/` 下第一层，`../../` 到仓库根，命中 `assets/`。

迁到 `src/shared/paths.js` 后仍是 `src/` 下第一层，**深度不变，这一行不用改**。这是把 `shared/*.js` 摊平、而不是塞进 `shared/config/` 的唯一原因——如果放进 `shared/config/paths.js`，就得改成 `../../../assets/`，多一处手工改动、多一处出错机会。

**验证方法**：起服务后打开 DevTools Network，确认 `naiwa_animated.glb`、`banana-cry-1.mp3` 的请求 URL 是 `http://127.0.0.1:2079/assets/...`，不是 `http://127.0.0.1:2079/src/assets/...`。

### 6.4 启动脚本的 `%~dp0` —— 会起不来，但报错明确

两个启动器都假设自己在仓库根：

```bat
:: 启动游戏.bat
cd /d "%~dp0"                    :: 改前
cd /d "%~dp0..\.."               :: 改后（scripts/launch/ → 仓库根）
start "hrg2079-server" /min node scripts\serve.mjs
```

```zsh
# 启动游戏.command
cd "$(dirname "$0")"             # 改前
cd "$(dirname "$0")/../.."       # 改后
nohup node scripts/serve.mjs </dev/null >/dev/null 2>>.server.log &!
```

注意 `.command` 里的 `.server.log` 是相对 cwd 写的，`cd` 改对之后日志会落在仓库根（和 `.gitignore` 里的 `.server.log` 条目一致），不用额外改。

**`.bat` 必须保持纯 ASCII + CRLF**（`.gitattributes` 已强制 `*.bat text eol=crlf`）。`git mv` 不改内容，行尾不受影响。

### 6.5 QA 脚本的 `_shots` 硬编码 —— 会静默写到错误位置

8 个脚本里有 `const out = '_shots/20261118'` 这类相对 cwd 的路径。目录搬走后它们会在仓库根**新建一个 `_shots/`**，截图散落，CI 的 `upload-artifact` 抓不到。

```bash

rg -l "_shots/" tests/e2e/*.mjs | xargs sed -i "s#'_shots/#'tests/e2e/shots/#g"
```

改完确认：


`tests/e2e/check_offline.mjs` 还硬编码了 `resolve('dist/活人感2079.html')`——`dist/` 位置不变，这条不用改，但**它要求先跑 `npm run build`**，CI 里要保证顺序。

### 6.6 Vitest alias —— 本次不需要改，但别顺手加路径别名

`vitest.config.js` 里只有两条 alias，都指向 `vendor/`：

```js

{ find: /^three$/, replacement: root + 'vendor/three/three.module.js' },
```

`vendor/` 不动，所以**这两条一个字都不用改**。真正要改的是 `tests/unit/*.test.js` 里的相对 import（8 个文件，见 §3.5）。

### 6.8 Git LFS 与 `git mv`

- `.gitattributes` 的 LFS 规则是**按扩展名**匹配的（`*.glb`、`*.mp3`…），`git mv` 不改扩展名，所以 LFS 跟踪关系自动跟着走，不需要重跑 `git lfs track`。
- **但 `git mv` 一个 LFS 文件时，Git 移动的是指针文件，不是实体。** 如果本地 LFS 对象缺失（`git lfs status` 显示 pending），`git mv` 之后 `git status` 会显示 modified。先 `git lfs pull` 再动手。
- 重命名检测的相似度阈值是 50%。本次每个文件只改 import 路径字符串，改动量远低于阈值，`git log --follow` 能一路追到重构前。**但如果有人顺手在同一个 commit 里格式化整个文件（`prettier --write`），相似度会掉到阈值以下，历史就断了。** 所以：**迁移 commit 只做迁移，格式化另开一个 commit。**

### 6.9 中文路径与大小写

- 仓库里已有大量中文路径（`docs/参考图/`、`assets/models/原始/`、`启动游戏.bat`）。GitHub Actions 的 `ubuntu-latest` 是 UTF-8 locale，`cp -r` / `find` 处理中文路径没问题。
- **但 `assets/models/原始/` 建议保持原样不要改成 ASCII**：`tools/assets/optimize_gen.mjs:11` 硬编码了 `resolve('assets/models/原始/gen')`，改名要同步改代码，收益为零。
- Windows 文件系统大小写不敏感、Linux 敏感。本次没有任何"只改大小写"的重命名，不触发这个坑。

### 6.10 本机 `rm -rf` 很慢

实测 `rm -rf .layertest`（64 个文件）耗时 20 秒以上，`rm -rf /tmp/xxx` 会直接卡住。迁移脚本里尽量用 `rmdir`（只删空目录，快且安全），需要递归删除时用 Node：

```bash
node -e "require('node:fs').rmSync('.layertest',{recursive:true,force:true})"
```

### 6.11 回滚

迁移全程在一个分支上，回滚成本极低：

```bash
# 还没提交
git checkout -- . && git clean -fd src tests tools docs scripts

# 已提交
git reset --hard origin/main
```

**不要**用 `git revert` 回滚迁移 commit——`git mv` 的 revert 会产生一堆删除+新增，历史更乱。直接 `reset --hard` 到迁移前的 commit。
