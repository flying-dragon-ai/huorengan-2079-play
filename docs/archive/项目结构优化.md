# 《活人感 2079 重制版》企业级架构重构与 GitHub 交付计划

## 摘要
在**不改动任何旧文件**的前提下，于并行目录 `app/` 重建一套行为等价、分层清晰、可工程化维护的源码（保留原生 JS ESM + vendored Three r187，零运行时 npm 依赖）；补齐 package.json / ESLint / Prettier / Vitest / esbuild 单文件构建 / GitHub Actions CI 与 JSDoc 类型。用机器人验收 + 单元测试对齐旧版后，把所有入口（路由）切换到新文件，再删除旧源码，最后以**全量 + Git LFS** 推送到新建私有仓库。玩法、画面、文案、交付物文件名零变化。

## 已锁定决策（问卷）
- **技术栈**：保留 JS + Three.js（vendored r187），新增开发期工程工具与 JSDoc 类型；不迁 TS、不引 Vite、不改运行时依赖策略。
- **重构深度**：行为保持重组——拆巨类、外提常量/配置/文案、清晰分层与模块边界、统一入口；`browser/` 观景版一并规范化。**不引入事件总线/状态管理框架**（那是未选中的 B 方案）。
- **仓库策略**：全量 + Git LFS + 推送到新建**私有**仓库（gh 已登录 `flying-dragon-ai`）。

## 2. 目标架构（行为保持）
新源码根在 Phase A 为 `app/`，cutover 后提升为规范名 `src/`（内部相对导入与资源相对深度不变，根改名安全）。**资源目录 `assets/`、`vendor/` 位置不动**，仅重组代码。

```
src/
├── main.js                 启动编排（等价旧 main.js）
├── core/        config.js（全局调参/路由/阈值）· paths.js（资源基址集中）· input.js · util.js · math.js
├── data/        text.js（文案/梗）· model-registry.js（MODEL_CONF）· quest-config.js
├── gfx/         pipeline.js · environment.js · textures.js · fx.js · shaders/（sanitize/grade 拆出）
├── world/       island.js（门面，组合下列模块，公开 API 不变）
│                terrain.js · roads.js · buildings.js · props.js · colliders.js · beach.js
│                districts/（8 街区组件 + kit.js + detail.js + plaza.js + refinements.js）
├── actors/      player.js · camera-rig.js · models.js · npc/（kangaroo/niulai/chaser/cardboard/peds）· figurines.js
├── game/        game.js（门面/主循环）· mission.js · auto-pilot.js · wanted.js · quality.js
│                districts.js（管理器）· ui.js · guide.js · hall.js · photo.js
└── audio/       audio.js
```

关键行为保持约束：
- `Island` 与 `Game` 保留为**门面类**，对外字段/方法签名不变（`heightAt/add/districts/cafe/auntSpot/shRows`；`state/phase/player/pipe/districts/dev/meter/laugh/fps` 等），内部委托拆出的模块。`window.__game` 与 `?dev=1` 工具（`jump/tp/ride`）接口不变，保证机器人验收脚本可用。
- **解除反向耦合**：路网常量 `XR/ZR/ROAD_W/BEACH_Z/shoreEdge/groundH` 移入 `world/terrain.js`+`core/config.js`，`guide.js`/`ui.js` 改从常量模块导入（不再 import `island.js`）。
- 资源路径集中到 `core/paths.js`（GLB/audio/img 基址），消除散落 `../../assets` 硬编码；保持加载结果等价。
- 巨类拆分纯属文件级重组，逻辑逐段搬移、不改算法；`text.js` 文案与 `MODEL_CONF` 数值原样保留。
- `browser/` 观景版规范化为 `src/viewer/`（独立入口 `viewer.html`），共用 `vendor/`，行为不变。
- 全部公共函数补 JSDoc 类型；不强制 `checkJS`（避免海量报错 churn），ESLint 兜底。

## 3. 工程化工具链（新增，均为新文件）
- `package.json`（type=module，private）脚本：`dev`(node 静态服务) · `build`(单文件) · `build:viewer` · `lint` · `format` · `test`(vitest) · `test:e2e`(机器人) · `check`(lint+test+build)。开发依赖：esbuild、eslint、prettier、vitest（仅 dev，运行时仍零 npm 依赖）。
- `eslint.config.js`（flat config，忽略 vendor/assets/dist）、`.prettierrc`、`.editorconfig`。
- `vitest.config.js` + `tests/unit/`：覆盖纯函数——`util`（clamp/lerp/damp/smooth/angleDamp/rng/Timeline）、`guide` 路网最短路（nearestRoad/routeTo，常量注入）、`data/text` 与 `model-registry` 完整性、`config` 不变量、`districts` 结算增益逻辑（纯部分）。不依赖 WebGL/DOM。
- `scripts/serve.mjs`：零依赖跨平台静态服务（127.0.0.1:2079，no-cache，队列 64），替代 python serve（clone 后仅需 Node 即可运行）。
- `scripts/build-singlefile.mjs` / `scripts/build-viewer.mjs`：esbuild API 复刻 `build_portable.py` 逻辑（`--minify-whitespace --minify-syntax`，**禁 `--minify`**；alias three/addons；base64 内嵌音频/GIF；`data-models="procedural"`；转义 `</script`；原子写），产出同名 `dist/活人感2079.html`、`dist/地球村-自由浏览.html`。
- `.github/workflows/ci.yml`：push/PR 触发 `actions/checkout`(lfs:true) → setup-node → `npm ci` → `lint` → `test` → `build`。另建 `e2e.yml`（workflow_dispatch 手动，装 Chrome 跑机器人验收）。
- `README.md`（中文为主，含运行/构建/测试/架构图/CI 徽章）、`LICENSE`（专有“All Rights Reserved”声明，引用 `assets/来源.md` 素材权利未核实）。

## 4. 分阶段执行（严格遵守“先建新→测试→切路由→删旧”）
**Phase 0 — Git 基线（不改旧文件）**：`git init` → `git lfs install` → 写 `.gitattributes`（LFS 追踪 `*.glb *.mp3 *.wav *.gif *.jpg *.jpeg *.png *.pdf *.mp4 *.webm`；`*.bat/*.cmd text eol=crlf`，`*.sh/*.command text eol=lf`）→ `.gitignore` → `git add -A && git commit -m "baseline: 原始项目快照"`。旧源码进入历史，天然可回滚。

**Phase A — 并行重建 + 测试（零旧文件改动）**：在 `app/` 写新分层源码；根目录新增 `index.next.html`（引用 `./app/main.js` + 现有 importmap）、工程配置、`scripts/`、`tests/`。`node scripts/serve.mjs` 起服务，新机器人脚本指向 `http://127.0.0.1:2079/index.next.html?dev=1|auto=1`。跑通验收门禁（§5）。此阶段旧 `src/ index.html tools/ browser/ 启动游戏.*` 一律不动。

**Phase B — 切换路由（测试通过后）**：以“删旧件+建新件”方式把全部入口指向新代码（不做原地修改）：删旧 `index.html`→建新 `index.html`（引 `./src/main.js`）；删旧 `启动游戏.bat/.command`→建新（调 `node scripts/serve.mjs` + Chrome）；删旧 `tools/build_portable.py`、`browser/build.py`→由 `scripts/build-*.mjs` 取代。删除旧 `src/`，将 `app/` 提升为 `src/`（纯根改名，内部相对路径与资源深度不变）；`browser/` 旧件删除、新观景源码就位 `src/viewer/` + `viewer.html`。删除 `index.next.html`。重跑验收于规范 `index.html` 确认。

**Phase C — 删除旧文件**：清除已被取代的旧 `tools/` 脚本（旧 cdp/check_*/diag_*/smoke.py/preview.html/model_check.html 等迁建到 `tools/qa|build|assets` 后删旧）、旧 `browser/` 残留。保留 `assets/ vendor/ blender/ tripo-out/ _shots/ dist/ 文档/参考图`（全量）。提交 `refactor: 切换入口并移除旧源码`。

**Phase D — GitHub 交付**：`gh repo create huorengan-2079 --private --source=. --remote=origin --push`（含 LFS 对象）。验证远端文件齐全、LFS 指针正确、CI 绿。

- **机器人 E2E（新入口，对齐旧基线）**：
  - `check_full`：自动演示从大厅跑到 `free`，**零控制台错误/警告**、约 60 fps、`meter/gags` 与旧版基线一致。
  - `check_entries`：两个观景入口（标题“先逛中央广场”、送单途中 P 暂停/恢复）通过。
  - `check_district` × 8（shanghai/tokyo/bigapple/beach/paris/pyramid/iceland/hometown）：任务全完成、专属笑点全触发、零报错。
  - 旧版基线先行采集（运行旧 `index.html` 一次记录 fps/meter/gags/报错），新版逐项比对。
- **离线单文件**：`dist/活人感2079.html` 以 `file://` 打开可启动、8 街区齐全、约 60 fps、零报错（与旧交付一致）。
- 任一项不达标则停在 Phase A 修复，**不进入 cutover**。

## 8. 风险与回滚
- **巨类拆分回归**：门面保持公开 API + 机器人逐项对齐旧基线；Phase 0 基线提交使任何阶段可 `git revert` 回滚。
- **资源相对路径**：集中到 `core/paths.js` 且保持目录深度，根改名 `app/→src/` 不影响加载。
- **单文件构建卡死**：沿用 `--minify-whitespace --minify-syntax`，禁 `--minify`（历史根因）。
- **LFS 配额/带宽**：212 MB 在免费额度内；CI checkout 启用 lfs。
- **bat 编码**：启动器纯 ASCII + CRLF（ host 硬约束），`.gitattributes` 强制 eol。
- **测试内存峰值**：机器人截图 1280×720（历史已验证避免 Chrome >2GB）。
